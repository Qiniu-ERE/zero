## 一、结论先说

| 平台 | 能不能做 | 一句话 |
|---|---|---|
| **Steam（Windows / macOS / Linux / Steam Deck）** | ✅ **首选** | 三个桌面包都已经能打，花 $100 就能上架；差的是**手柄支持**、商店版和改名 |
| **Xbox · PC（Microsoft Store）** | ✅ 可以 | 个人开发者注册免费（2025-09 起），Windows 包用 MSIX 封装后提交；和 Steam 共用大部分准备工作 |
| **Apple App Store（iPhone / iPad）** | ⚠️ 可以，有前提 | 已经能出不签名的 IPA；要 Apple 开发者账号（$99 / 年）、用 Xcode 26 / iOS 26 SDK 重新编译签名。**中国区要版号，不上**；只上其他地区 |
| **Google Play** | ⚠️ 要先升级引擎 | 新应用必须交 AAB、目标 API 36（2026-08-31 起），64 位原生库要支持 16 KB 页（更新包从 2027-02-01 起强制）。spx 现在的 Android 模板是 Godot 4.4.1、只能出 APK、目标 API 34，**做不到**。要等 spx 升级 Godot 或者自己改 |
| **Xbox · 主机（Series X\|S）** | ❌ v5 只评估 | 需要公司主体加入 ID@Xbox、Godot 的主机移植（W4 Games 等第三方，收费）；更根本的是 **spx 的游戏逻辑跑在 Go 写的解释器里，Go 不支持主机系统**。要上主机只能把游戏逻辑改写成 GDScript（见 TECH.md 第五节），Steam 卖得好再考虑 |

**怎么赚钱**（2026-10-28 更新）：**免费玩看广告，$0.99 一次性去广告**。欧美手机（App Store / Google Play）和国内微信小游戏免费下载，复活、金币翻倍时玩家自愿看激励视频，横幅只放在战场外；付 $0.99 永久去广告。Steam 不允许游戏里放广告（含激励视频），所以 PC（Steam、Microsoft Store）统一 **$0.99 买断**。spx 现在接不了广告 SDK，所以先上 PC，广告接通后（约第 4 个月）再上手机和微信小游戏。详见 [MONETIZATION.md](MONETIZATION.md)。

**怎么让人知道**：不买量，推广 ¥0：靠微信分享、双人合作拉朋友、地图编辑器做内容；Steam 的 Coming Soon 页、Couch Co-Op Fest、Next Fest 都是免费曝光。详见 [MARKETING.md](MARKETING.md)。

**盈利预期**（推测，假设见 [CASHFLOW.md](CASHFLOW.md) 第三节）：总投入 **¥3350**（AI ¥1850 + 上架费 ¥1500）。基准情景每天 48 个新玩家，**第 6 个月回本，第一年净赚约 ¥5700**，之后每年约 ¥1 万；保守（每天 16 人）第 12 个月回本、第一年打平；乐观（每天 208 人）第 4 个月回本、第一年约 ¥3.2 万。路演讲法见 [PITCH.md](PITCH.md)。

**体验上最大的缺口是手柄**：Steam Deck 认证、远程同乐、手机上的双人合作都靠它；而且 Steam Input 的键盘模拟会把两只手柄合并成一个键盘，双人合作没法用，必须在游戏里按设备区分。详见 [EXPERIENCE.md](EXPERIENCE.md)。

## 二、现状：离“能上架”还差什么（代码）

| 项目 | 现在 | 上架需要 |
|---|---|---|
| **手柄** | **完全不支持**。spx 没有给游戏脚本提供手柄接口（源码里只有网页版引擎的 JS 库里有手柄代码），游戏只认键盘、鼠标、单指触屏 | Steam Deck 认证、Xbox 都要求手柄能玩全部内容，按键提示要显示手柄图标 |
| **模拟广告** | 主页横幅（“七牛云 · 本广告位招商中”）、右侧原生广告卡、复活和金币 ×2 的模拟激励视频 | **付费游戏里不能有假广告**。商店版全部去掉：复活改成每局一次免费复活（或金币复活），金币 ×2 去掉 |
| **名字** | 英文标题就是 `BATTLE CITY`（`strings.py`），这是原作（Namco 1985）的名字 | **已定（2026-10-25）**：中文保留“坦克大战 2026”，英文改为 **Brickline Tanks**（查过没有同名游戏；“Tank Battle 2026”在 itch.io 上已有人用）。见 [PLATFORMS.md 第七节](PLATFORMS.md#七知识产权上架前必须处理)、[STORE.md](STORE.md) |
| **存档** | 只有 PC 版能存一张自制地图；金币、最高分不保存 | 至少保存最高分、通关进度、设置、金币和外观 |
| **桌面包** | Windows / macOS / Linux 单文件程序；第一次运行把引擎解压到用户缓存目录 | Steam 直接用；Windows 包可能被杀毒软件误报（自解压），要观察 |
| **Android** | 调试证书签名的 APK，Godot 4.4.1 模板，目标 API 34，NDK r23c 编译的 Go 库 | AAB、正式签名、目标 API 36、16 KB 页对齐 |
| **iOS** | 不签名的 IPA，CI 上用 Xcode 编译 | Xcode 26 / iOS 26 SDK 编译、开发者证书签名、隐私清单 |
| **打包环境** | GitHub Actions 额度用完（2026-10-25），只能本机打包；本机没有 Xcode，磁盘只剩约 9 GB | iOS 需要一台装 Xcode 26 的 Mac（Xcode 本身要几十 GB） |

## 三、游戏内容调整

### 3.1 去掉“每日挑战”

**现状（代码）**：主页模式列表的第三张卡是“每日挑战 · 即将推出”（`build.py` 的 `HOME_MODES` 里 `("m.daily", "")`，文案在 `strings.py` 的 `m.daily`、`m.daily.d`）。它是灰色占位，`UI.spx` 里没有点击处理，按任何键也进不去。这个点子来自 v2.0 规划（“AI 每天生成一张地图，全服同图排名”），需要服务器和排行榜，v5 里不做；v6.0 重新规划（见 [v6.0 规划](../v6/PLAN.md)）。

**为什么去掉**：商店审核和玩家都不喜欢“即将推出”的空入口；它还占着主页的位置，会让人以为游戏没做完。

**怎么改**（实施时一个 PR）：

| 文件 | 改动 |
|---|---|
| `tools/assets/build.py` | `HOME_MODES` 去掉 `("m.daily", "")`；“即将推出”徽章的绘制代码（`soon`）随之不用，可以删掉 |
| `tools/assets/strings.py` | 删掉 `m.daily`、`m.daily.d`、`soon` |
| 主页布局 | 剩下“双人合作”“自己做地图”两张卡，重新排间距（或者把空位留给以后的“观看演示”） |
| 生成文件、`.xbp` | 重新运行 `build.py`、`package_xbp.sh` |
| 文档 | README 主页截图、[v3.0 规划](../v3/PLAN.md)的 P2 里“每日挑战”一项标成“v5 取消” |
| 测试 | v4 的主页流程测试（`tests/spx/flow_home.spx`）确认主页只有三个入口（开始战役、双人合作、自己做地图） |

### 3.2 自己的子弹能打掉自己的老鹰

**规则**：和 FC 原版一样，**玩家的子弹打中自己的基地也算失守**。README 的玩法说明已经这样写（“基地被击中（自己的子弹也算）”）。

**现状（代码 + 实测）**：

- `hitPoint()` 打到基地格（`grid == 9`）就调用 `baseDestroyed()`，**不区分是谁的子弹**。唯一的例外是路演演示模式（主页按 P，`autopilot`）：演示时基地打不掉，由演示脚本安排“防线失守”。
- 2026-10-25 用 v4 的引擎内测试框架做了一次实测（临时测试，没有提交）：第 1 关开局，让 1P 在出生点朝右（基地方向）真实发射子弹：

```
INFO base -72 -150 player -120 -150 cellL 1 cellU 1
INFO shot 1 left cell 3 baseDown false state 1     ← 第 1 发：护墙砖裂开
INFO shot 2 left cell 0 baseDown false state 1     ← 第 2 发：护墙砖碎了
INFO shot 3 left cell 0 baseDown true state 2      ← 第 3 发：老鹰被打掉，进入复活询问
TEST PASS 1P 从出生点往右打，打掉自己的老鹰
```

也就是说，**能打死，只是要先打穿护墙**：老鹰四周有一圈砖墙，每块砖要打两下（[PR #20](https://github.com/Qiniu-ERE/zero/pull/20) 修好的规则），所以从出生点打要第 3 发才打到老鹰。v3.0.1 之前砖墙一发就碎，那时第 2 发就能打掉。

**看起来“打不死”的几种情况**：

| 情况 | 原因 |
|---|---|
| 在路演演示模式（主页按 P）里打 | 演示模式故意让基地打不掉 |
| 只打了一两发 | 护墙砖还没打穿 |
| 从侧面靠近、子弹擦过护墙边缘 | 子弹打在旁边的格子上，没有命中基地格 |

**v5 要做的**（不改游戏规则）：

- 把上面的实测写成正式的回归测试：真实发射子弹，覆盖“从出生点往右打”“从上方往下打”“2P 打自己的基地”和“演示模式打不掉”四种情况（**已在 [#71](https://github.com/Qiniu-ERE/zero/pull/71) 完成**，编号 C21~C24，因为 C05~C20 已被占用；三种打法都是第 3 发打掉老鹰）。现在的 C04 只直接调用 `hitPoint()`，没有覆盖子弹真正飞过去的过程。
- 商店版的新手提示里写明“小心别打到自己的老鹰”。

## 五、为什么先做 Steam

- **包已经有了**：三个桌面平台的单文件程序 v3.0 起就能打，Linux 包在 Steam Deck 上原生运行（Steam Deck 是 x86_64 Linux）。
- **门槛最低**：个人可以注册，每款游戏一次性 $100，销售额达到 $1000 后返还（公开资料）。
- **卖点契合**：本地双人合作 + Remote Play Together、地图编辑器，在 Steam 上都是常见的标签。
- **验证成本低**：先开“即将推出”页面和免费试玩版，用**愿望单数量**判断值不值得继续投入，不用先花大钱。
- **手柄是共同前提**：为 Steam Deck 做的手柄支持，以后 Xbox、iPad 外接手柄都能用。
