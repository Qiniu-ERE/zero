# 坦克大战 v5.0 · 规划总览：商业化落地探索

> **本版先只做文档**：评估“这个游戏怎么真正赚到钱”，定下要验证什么、按什么顺序做、每一步做到什么程度算成功。文档合入后，再按第五节的拆分逐个 PR 实施。
>
> 依据分三类，文中都已标明：
> - **代码**：读本仓库 `main`（v3.0.2，`fc7e64e`）确认的现状。
> - **公开资料**：2026-10-25 查阅的平台文档和公开报道。平台规则经常变，**上线前要重新核对**。
> - **推测**：没有条件验证的判断，包括所有收入数字。

v2.0 做出了现代画风和 4 个**模拟**广告位，v3.0 做出了 8 个关卡、自己做地图、双人合作和六个平台的安装包，v4.0 补上了自动化测试。到现在为止，游戏**一分钱都没有赚过**：广告是游戏里画出来的，金币只是结算画面上的一个数字，安装包只放在私有仓库的 Releases 里。

v5.0 要回答三个问题：**在哪里上线、靠什么赚钱、要满足哪些前提**。

| 方向 | 内容 | 状态 | 详细文档 |
|---|---|---|---|
| **1. 变现设计** | 激励视频接入真实广告；金币有用处（皮肤、地图槽位）并能保存；去广告的一次性购买；不卖数值 | 📝 方案已定 | [MONETIZATION.md](MONETIZATION.md) |
| **2. 渠道与合规** | 海外 H5 门户、自有网页（七牛云 CDN）、微信小游戏、Google Play、国内商店、Steam / itch.io 逐个评估；版号、软著、备案、防沉迷、隐私、IP | 📝 评估完成 | [CHANNELS.md](CHANNELS.md) |
| **3. 技术前提** | 游戏和宿主之间的桥（广告、支付、埋点都靠它）、存档、数据埋点、远程配置、正式签名 | 📝 方案已定，桥未验证 | [TECH.md](TECH.md) |
| **4. 定制与授权（B2B）** | 用地图编辑器做企业年会 / 品牌活动的定制版；作为 XBuilder 教学案例授权 | 📝 方向已定 | 本文第三节 |

## 一、现状：离“能收钱”还差什么（代码）

| 项目 | 现在 | 要变成 |
|---|---|---|
| 激励视频 | `watchAd()` 广播 `adFlow`，播 5 秒示例素材后直接发奖励 | 调用平台广告 SDK，**看完才发奖励**；加载失败时给不看广告的替代方案 |
| 横幅、原生广告卡 | 游戏里画的造型，写着“模拟广告位” | 平台的原生组件盖在预留位置上，或者干脆去掉（看渠道规则） |
| 金币 | 结算时按本关得分折算，**不保存、也没有地方花** | 保存下来，能买皮肤 / 地图槽位，能代替广告换复活 |
| 钻石复活 | 复活询问里画了“50 钻石复活”，**点了没有反应** | 要么做成真的（需要内购，见合规），要么改成“金币复活” |
| 最高分 | 只在本次运行内有效 | 保存；以后可以有排行榜 |
| 存档 | 只有 PC 版能保存自制地图（`os.UserConfigDir()`）；网页版保存会失败 | 所有平台都能保存进度、金币、设置、地图 |
| 数据 | 没有任何统计 | 知道多少人玩、玩到第几关、在哪里流失、看广告的比例 |
| 安装包 | Android 用调试证书签名，iOS 不签名，网页版要自己找地方放 | 商店要求的正式签名包；网页版有固定的 HTTPS 地址 |

结论：**最大的卡点是“游戏脚本没法调用外部 SDK”**。广告、支付、埋点、排行榜都卡在这里（见 [TECH.md 第一节](TECH.md#一宿主桥)）。所以 v5 的第一件事是验证这座桥，桥不通，后面的变现方案只能停在网页外壳能做的范围内。

## 二、结论先说

| 问题 | 结论 |
|---|---|
| **先上哪里** | **海外 H5 游戏门户（CrazyGames 等）+ 自有网页版**。不需要版号、软著和备案，网页版已经有了，门户自带流量和广告分成。目的不是赚多少钱，而是**用最低成本拿到真实玩家数据**（留存、关卡流失、看广告的比例） |
| **国内主渠道** | **微信小游戏，只做广告变现（IAA），不做内购**。按 2026 年的公开资料，不开内购可以不要版号，但要软著（或电子版权认证）、自查报告和 ICP 备案；技术上的卡点见 [v3.0 微信小游戏评估](../v3/WECHAT_MINIGAME.md) |
| **变现方式** | 以**玩家自愿的激励视频**为主（复活、金币 ×2），加一个**去广告**的一次性购买（只在有正式支付的渠道）。**不卖数值**，不在战场里放广告，延续 v2.0 的原则 |
| **商店 App** | 放在后面：Google Play 个人账号新应用要先 12 人连续 14 天封闭测试；国内安卓商店和 App Store 中国区都要版号 / 备案，个人很难走通 |
| **Steam** | 可以作为“买断制 PC 版”试一试，但游戏体量小，买断收入预计很有限，优先级最低 |
| **B2B** | 企业年会、品牌活动的**定制关卡版**可能是最快拿到真金白银的路：地图编辑器已经做好，定制成本低；不涉及向玩家收费，合规负担小 |
| **最大风险** | ① 宿主桥能不能做通；② “坦克大战”的名称和玩法辨识度（原作是 Namco 的 *Battle City*），商业化前要改名并做出足够差异；③ 软著对 AI 辅助生成代码的审核趋严 |

## 三、定制与授权（B2B）

v3.0 的地图编辑器让“做一张新地图”从改代码变成了画几分钟，这正好是定制业务最需要的能力。

| 方向 | 做什么 | 卖给谁 | 需要的改动 | 风险 |
|---|---|---|---|---|
| **年会 / 团建版** | 公司 Logo 拼成的地图、公司吉祥物当基地、关卡名换成部门名；网页版扫码就玩，排行榜按部门 | 企业行政、HR | 换主题色和基地造型（`build.py` 生成，改参数即可）、开局文案、关卡数据；排行榜需要后端 | 每单都要改，必须把“换皮”做成配置，否则做不过来 |
| **品牌活动版** | 品牌元素做成**可选的**皮肤和特别关卡，通关领优惠券 | 品牌方、营销公司 | 同上，加兑换码接口 | 和“战场里没有广告”的原则冲突：只做玩家主动进入的“活动关卡”，常规关卡不放 |
| **教学案例** | 整个工程（含 v4 的测试、v3 的跨平台打包）作为 XBuilder / XGo 课程案例 | 培训机构、七牛云 / XBuilder 生态 | 整理成分步课程；代码已开源友好（spx Apache-2.0、字体 OFL、素材原创） | 收入天花板低，但和比赛主题、七牛生态最契合 |
| **七牛云广告位** | 主页横幅现在写的就是“七牛云 · 本广告位招商中”，可以作为自家产品（Kodo、CDN）的推广位 | 七牛云 | 无（已有） | 不是外部收入 |

建议先做一个**年会版样板**（第五节 P2），用来对外演示和报价。

## 四、范围

**做**：

- 文档：本文、[MONETIZATION.md](MONETIZATION.md)、[CHANNELS.md](CHANNELS.md)、[TECH.md](TECH.md)（本 PR）。
- 技术验证：宿主桥、网页版存档、埋点（都不需要任何平台账号，可以先做）。
- 第一个真实渠道：网页版接入一个海外 H5 门户的 SDK，用真实玩家数据决定后面要不要继续。
- 金币有用处、能保存。

**不做**：

- 卖数值（更强的子弹、更多的命直接卖钱）、抽卡、体力限制。
- 在战场里放广告，或者在对局中弹出广告。
- 在没有版号的情况下做内购；在不确定的合规问题上“先上了再说”。
- 联网对战（成本高，和变现验证无关）。
