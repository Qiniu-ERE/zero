# 坦克大战 v5.0 · 变现设计

> [v5.0 规划](PLAN.md)的第一个方向。依据的标注方式同规划总览：**代码**、**公开资料**（2026-10-25 查阅）、**推测**。本文所有收入数字都是**推测**，只用来说明怎么算，必须用上线后的真实数据替换。

## 一、原则（延续 v2.0）

[v2.0 设计](../v2/DESIGN.md#四广告干净不打扰)定下的规则继续有效，商业化之后**不放宽**：

- **战场里没有广告**，对局中不弹广告。
- **激励视频完全自愿**，而且每个用广告换的奖励都有**不看广告的替代方式**。这也是 CrazyGames 对激励广告的要求（公开资料：官方文档建议复活按钮每局限一次，并提供用金币等方式获得奖励的途径）。
- **不卖数值**：花钱或看广告只能换“继续玩”（复活）、“多拿金币”和外观，不能换更强的坦克。排行榜才有意义，家长和平台审核也更放心。
- 广告按钮蓝色、带“广告 / Ad”标识，游戏按钮橙色（v2.0 已实现）。

## 二、广告位：按渠道取舍

| 广告位 | 现在（代码） | 自有网页版 | CrazyGames 等 H5 门户 | 微信小游戏 | 安卓 App |
|---|---|---|---|---|---|
| 复活激励视频 | 模拟，每局第一次战败 | 先不接（没有合适的广告源，见下） | ✅ SDK 激励视频 | ✅ `wx.createRewardedVideoAd` | ✅ AdMob 激励视频（需要 Android 插件） |
| 金币 ×2 激励视频 | 模拟，结算时可选 | 同上 | ✅ 同上 | ✅ 同上 | ✅ 同上 |
| 主页横幅 | 游戏里画的造型 | 留作七牛云自家推广 | ⚠️ 门户可以在游戏外放横幅，游戏内横幅按 SDK 规则（每屏最多 2 个，对局中不许） | Banner 广告组件，原生组件盖在画布上 | AdMob 横幅 |
| 对局右侧原生广告卡 | 游戏里画的造型 | **去掉** | **去掉**（门户禁止对局中出现横幅） | 原生模板广告，**建议先不放** | **去掉** |
| 关卡间插屏 | 没有 | 不加 | 门户 SDK 有“midgame”插屏，最多 3 分钟一次；**v5 先不加**，等数据再决定 | 不加 | 不加 |

说明：

- **对局右侧的原生广告卡在所有真实渠道都去掉**。它在路演里用来展示“广告不挡战场”，但门户规则不允许对局中出现横幅，原生组件在小游戏里还要做坐标换算（[v3.0 评估 4.1](../v3/WECHAT_MINIGAME.md#41-广告位对照)），收益又最低。去掉后右侧面板可以放关卡目标或金币。
- **自有网页版先不接广告**。Google 的 H5 Games Ads（AdSense for Games）需要申请并通过审核，网站还要有足够的内容和流量（推测）；自有网页版的定位是“对外演示 + 年会版投放”，不靠它赚钱。
- **只能用平台指定的广告**：门户要求只用自家 SDK 的广告、不能有外部广告；微信要求接官方广告组件（公开资料）。所以广告抽象层要按渠道切换实现，不能写死一家。

## 三、金币经济

### 3.1 现在（代码）

- 结算金币 = （本关得分 − 开局得分）÷ 50，通关再加 100。每关 20 辆敌人，每辆 100 / 200 / 400 分，所以**通关一关大约拿到 140~260 金币**，看视频翻倍。
- 金币**不保存**，也**没有地方花**；复活询问里的“50 钻石复活”点了没有反应。

### 3.2 v5 的设计

**来源**

| 来源 | 数量 | 说明 |
|---|---|---|
| 结算 | 维持现在的公式 | 失败也有（按得分），鼓励再试 |
| 结算看视频 | ×2 | 每关一次 |
| 每日首次通关 | +100 | 给回访一个理由；需要存档记日期 |
| 自制地图被试玩通关 | +50 | 只在有分享功能之后（v5 不做） |

**用途**

| 用途 | 价格（推测，要调） | 说明 |
|---|---|---|
| **金币复活** | 300 | 代替现在点不了的“钻石复活”，和激励视频复活二选一，每局一次。满足“奖励有不看广告的替代方式” |
| 坦克皮肤 | 1500~3000 | 颜色和涂装，`build.py` 生成造型时加参数即可；1985 像素风保持免费 |
| 基地造型 | 2000 | 同上 |
| 地图槽位 | 1000 / 个 | 编辑器现在只能存一张图（`maps.txt`）；免费 1 个，最多 5 个 |

按这个价格，一个皮肤大约要通关 8~15 关（看视频减半）。8 关全通一遍能买一个皮肤，这个节奏是**推测**，要看真实的关卡完成率再调。

**存档**：金币、已购物品、最高分、每日记录、设置（画风、语言）、地图槽位，放在一个存档文件里，带版本号，方便以后加字段。各平台怎么存见 [TECH.md 第二节](TECH.md#二存档)。

**防作弊**：单机游戏的存档可以被改，v5 不防。等有了排行榜，排行榜的分数要由服务器校验（v5 不做排行榜）。

## 五、指标与决策

### 5.1 埋点要回答的问题

| 问题 | 指标 | 事件（见 [TECH.md 第三节](TECH.md#三数据埋点)） |
|---|---|---|
| 玩家留不留得住 | 次日 / 7 日留存、人均会话时长、人均局数 | `session_start`、`session_end` |
| 难度对不对 | 每关的开始数、通关率、平均用时、在哪关流失 | `stage_start`、`stage_end`（结果、用时、得分） |
| 广告愿不愿意看 | 复活询问时选看视频 / 金币 / 放弃的比例；金币 ×2 的点击率；广告加载失败率 | `ad_offer`、`ad_start`、`ad_reward`、`ad_fail` |
| 新玩法有没有人玩 | 双人合作、编辑器的进入率和使用时长 | `mode_enter` |
| 金币经济是否合理 | 人均金币余额、第一次购买的时间、最常买的东西 | `coin_earn`、`coin_spend` |

### 5.2 收入怎么算

```
每日收入 ≈ 日活 × 人均每日看激励视频次数 × 填充率 × eCPM ÷ 1000 × 渠道分成比例
```

- **人均次数**：复活每局最多一次，金币 ×2 每关一次。设一个人一天玩 3 局、平均每局 2 关，上限约 3 + 6 = 9 次；实际看的比例才是关键，只能上线后测。
- **eCPM**：每千次展示的收入，和国家、平台、季节关系很大，公开资料里差距可以是几倍到十几倍，这里**不给数字**。上线后从广告后台读。
- **分成**：CrazyGames 不公开分成比例，按用户量、广告表现等每月结算，满 €100 付款（公开资料）；微信流量主按其公布的比例分成，开通流量主有门槛（见 CHANNELS.md）。

示例（**全部是假设，只演示计算**）：日活 1000，人均每天看 1.5 次，填充率 80%，eCPM 记作 E，分成 50%，每日收入 ≈ 1000 × 1.5 × 0.8 × E ÷ 1000 × 0.5 = 0.6E。也就是说，**日活一千的规模，每天的收入大约是 eCPM 数值的六成**。要赚到有意义的钱，靠的是日活和人均次数，所以 P2 的重点是留存数据，不是广告位的数量。

### 5.3 决策点 2 的标准（推测，上线第一周校准）

| 指标 | 继续扩渠道 | 先改游戏 |
|---|---|---|
| 次日留存 | ≥ 20% | < 10% |
| 人均会话时长 | ≥ 8 分钟 | < 4 分钟 |
| 复活询问选择看视频的比例 | ≥ 30% | < 10% |
| 第 1 关通关率 | ≥ 60% | < 40%（太难，新手流失） |

介于两者之间就再观察两周，同时调难度和新手引导。
