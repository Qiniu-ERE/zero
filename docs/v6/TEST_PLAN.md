# 坦克大战 v6.0 · 测试方案：全覆盖

v6 沿用 v4 的测试框架（[v4 测试方案](../v4/TEST_PLAN.md)：引擎内测试、构建工具测试、网页外壳测试、覆盖率基线），要求从“基线不降”提高到**全覆盖**。日常命令见[架构文档第 10 节](../ARCHITECTURE.md#10-测试与演示视频)。

## 一、要求和怎么检查

| 指标 | 要求 | 谁来检查 |
|---|---|---|
| 用例清单 | 本文第三节的**每个用例 ID 都有测试**（断言说明或测试方法名以 ID 开头） | `spx_coverage.py report`：v6 的 ID 少一个就失败（`pr_check.sh --coverage` 不通过） |
| 函数和事件处理 | v6 新增和改动的函数、事件处理全部被测试执行到；整体不低于基线 | `spx_coverage.py` 和 `tests/coverage-baseline.json` 比较：新加的没有执行到、原来覆盖的掉了，都失败 |
| Python 行覆盖 | v6 新增的工具（`tools/levels/daily.py`、`server/leaderboard.py`）**100%**；`check.py`、`strings.py` ≥ 85% | `tools/test/py_coverage.py --check`（只用标准库的 `trace`，`run_all.sh --coverage` 会调用） |
| 克隆预算 | 常驻的 UI 克隆 + 最满的地图（169 格）+ 坦克子弹爆炸（30 个）≤ 300 | `tests/spx/budget.spx`（Q01~Q03）、`tests/tools/test_daily.py`（Q04） |
| XBuilder 兼容 | spx v3.3.0 能编译 | `tools/test/xbuilder_check.sh`（T09） |

按键和点击的处理（`onKey`、`onClick`）在无界面测试里触发不了：处理里只调一个舞台函数（例如三选一的 1 / 2 / 3 都调 `pickChoose`），测这个函数。全屏画面上的按钮点击都走 `UI.clickAt(x, y)`，测试直接用舞台坐标调用它模拟点击（S10、S11）。

## 四、测试发现的问题

| 问题 | 怎么发现的 | 怎么修的 |
|---|---|---|
| 排行榜、车库这些画面的小部件常驻时，克隆超过 300 个，地图格子和敌人出不来（不报错） | 文档截图时发现战场是空的；查 spx 源码 `shape_manager.go` 的 `maxClones = 300` | 全屏画面的小部件按需创建（`panelOff`），加克隆预算测试 Q01~Q04 |
| 三选一测试偶尔失败：前一步随机装上的芯片不会再被抽到 | 跑全部测试时偶发 | U10 先清空芯片 |
| 连携提示测试偶尔失败：装芯片、组成连携会推进每日任务，任务刚好完成时“任务完成”的提示盖掉了连携提示；任务按日期抽，所以只在某些日子出现 | 生成覆盖率基线时 U24 失败（`got=msg.task.done`） | U24 前先把今天的任务都算完成 |
| 每日挑战的敌人出场和三选一共用一个随机序列：第几次三选一抽到什么，会受“捡芯片之前出了几辆敌人”影响，大家抽到的不一定一样 | D06 偶发失败（等待期间出兵协程先消耗了一次随机数） | 拆成两个独立的序列（`dailyRand` / `dailyChipRand`）；D06 加一条“出兵不影响三选一” |
| 排行榜底部“我的名次”在没上榜时显示错乱：名次返回 `-`，数字字体里没有这个字符，克隆留着创建时的造型（对局顶栏的关卡名）；总人数和 0 分叠在“你还没上这个榜”上 | 本机模拟上线（`server/deploy/local.sh`）时截图发现；之前的截图里玩家都已上榜 | 没上榜时 `lbText` 这一行都返回空；R06 加三条断言 |
| spx 解释器里没有 `time.Now` | 编译报错 `unreachable` / `undefined: time.Now` | 用临时文件的修改时间（`nowSec`），网页版用排行榜服务器的日期 |
